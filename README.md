# الذاكرة الرقمية للأجيال — Family Vault

تطبيق ويب يتيح محادثة شخصيات افتراضية من أجيال مختلفة لاستعادة ذكريات الماضي،
محميّ بـ **بوابة تحقّق ثلاثية** تعمل بالكامل داخل متصفّح المستخدم.

الموقع المنشور: <https://abdullahalialhammadi-aa.github.io/family-vault/>

---

## بوابة التحقّق

يمرّ المستخدم بخمس خطوات قبل الوصول إلى المحتوى:

| # | الخطوة | التقنية |
|---|--------|---------|
| 1 | الحساب وكلمة المرور | تجزئة SHA-256 عبر Web Crypto |
| 2 | رمز مؤقّت TOTP | RFC 6238 عبر HMAC-SHA1 |
| 3 | بصمة الجهاز | WebAuthn بمستشعر مدمج |
| 4 | بوابة الوجه | face-api.js داخل الجهاز |
| 5 | العنصر الحي | Teachable Machine للتعرّف على Coffee أو Mouse |

بين الخطوتين الثالثة والرابعة تظهر **شاشة موافقة صريحة** قبل تشغيل الكاميرا.

### تخطّي الخطوات

كل خطوة بعد تسجيل الدخول فيها زر **تخطّي**، ليعمل العرض على جهاز تنقصه بعض
الإمكانات. تخطّي شاشة الموافقة يتخطّى بوابة الوجه والعنصر الحي معاً، لأن
الكاميرا لا تعمل بلا موافقة.

التخطّي ظاهر لا خفيّ: يُسجَّل في سجل المحاولات كعدم اجتياز، وتتحوّل دائرة الخطوة
في المؤشّر إلى اللون البرتقالي، ويصبح ملخّص النهاية صندوق تحذير يعدّ العوامل
المتخطّاة.

لإلزام المستخدم باجتياز كل العوامل، اجعل `ALLOW_SKIP` في أعلى الكود `false`
فتختفي كل أزرار التخطّي.

### تفاصيل كل عامل

**رمز TOTP.** عند أول دخول يولَّد مفتاح عشوائي بطول 160 بت، يُعرض كرمز QR
وكنص لإدخاله يدوياً في تطبيق مصادقة مثل Google Authenticator. لا يُفعَّل المفتاح
إلا بعد أن يُدخل المستخدم رمزاً صحيحاً مولّداً منه. التحقّق يقبل فارق فترة واحدة
في الاتجاهين لتحمّل انحراف ساعة الجهاز.

**بصمة الجهاز.** التسجيل ينشئ مفتاحاً عبر WebAuthn بمستشعر الجهاز المدمج، ويُحفظ
معرّف المفتاح فقط. المفتاح الخاص لا يغادر الجهاز ولا يصل إلى الموقع. التحقّق يفحص
ثلاثة أمور: أن المفتاح العائد هو نفسه المسجّل للحساب، وأن تجزئة نطاق الموقع داخل
الاستجابة تطابق النطاق الحالي، وأن علمَي حضور المستخدم وتحقّق بصمته مرفوعان.

**بوابة الوجه.** تُحوَّل لقطة الكاميرا إلى واصف رقمي من 128 رقماً، ويُقارن بالواصف
المحفوظ بالمسافة الإقليدية. **لا تُحفظ أي صورة إطلاقاً.** الكاشف يجرّب سلّم أحجام
إدخال لأن الوجه القريب والوجه البعيد يحتاجان حجمين مختلفين.

## الخصوصية والبعد القانوني

- الموافقة تُطلب صراحةً **قبل** أي تشغيل للكاميرا، والرفض يوقف العملية.
- يُخزَّن **واصف رقمي لا صورة**، ولا يمكن إعادة بناء الوجه منه.
- كل البيانات في متصفّح الجهاز وحده، ولا تُرفع إلى أي خادم.
- زر **حذف الواصف نهائياً** متاح في أي وقت، مع أزرار منفصلة لحذف بصمة الجهاز
  ومفتاح TOTP أو حذف كل بيانات الأمان دفعة واحدة.
- **سجل المحاولات** يعرض آخر خمسين محاولة بنجاحها وفشلها.

## الشرط الجوهري: HTTPS

بصمة الجهاز والكاميرا **لا تعملان بدون HTTPS**. الموقع المنشور على GitHub Pages
يستخدم HTTPS تلقائياً. عند فتح الصفحة بدونه يظهر تحذير أحمر في أعلى البطاقة.

## التشغيل محلياً

### خادم Node المدمج

```bash
npm run serve
```

يطبع رابطاً محلياً على `localhost`. استخدم `localhost` لا `127.0.0.1`، لأن WebAuthn
يرفض عناوين IP كنطاق.

### عبر XAMPP

اربط المستودع بمجلّد `htdocs` بوصلة مجلّد حتى تنعكس التعديلات فوراً بلا نسخ:

```cmd
mklink /J "C:\xampp\htdocs\family-vault" "C:\dev\family-vault"
```

ثم شغّل Apache من لوحة تحكّم XAMPP وافتح:

<http://localhost/family-vault/>

يعتبر المتصفّح `localhost` سياقاً آمناً، فتعمل الكاميرا وبصمة الجهاز رغم غياب HTTPS.
وملف `.htaccess` في المستودع يمنع الوصول عبر الويب إلى مجلّد git والاختبارات والسكربتات.

بيانات التحقّق مرتبطة بالنطاق: ما تسجّله على `localhost` لا يعمل على النطاق المنشور
والعكس، فلكلٍّ منهما تهيئة مستقلّة.

## الاختبارات

لا توجد أي حزم خارجية. الاختبارات تعتمد على Node 22 فأحدث ومتصفّح Chrome مثبّت.

```bash
npm test          # فحوص ثابتة + خوارزمية TOTP، ثوانٍ معدودة
npm run test:flow # البوابة كاملة داخل متصفّح حقيقي
npm run test:all  # الكل
```

| الملف | ما يغطّيه |
|-------|-----------|
| `tests/structure.test.mjs` | وجود الملفات والدوال، تثبيت إصدارات المكتبات، ضوابط الأمان |
| `tests/totp.test.mjs` | Base32 مقابل RFC 4648، و TOTP مقابل متجهات RFC 6238 المرجعية |
| `tests/flow.test.mjs` | تدفّق البوابة كاملاً في Chrome، بمستشعر بصمة افتراضي وكاميرا وهمية |

اختبار المتصفّح يُنزّل صور وجوه للاختبار عند التشغيل إلى `tests/.fixtures/`
وهو مجلّد متجاهَل في git، فلا تُحفظ صور أشخاص داخل المستودع.

## الرفع والنشر

```bash
sh scripts/push.sh "وصف التعديل"
```

يفحص، يجلب آخر التحديثات، يلتزم، ويرفع. صفحات GitHub تنشر التحديث خلال دقيقة تقريباً.

لتفعيل منع الرفع عند فشل الفحوص:

```bash
git config core.hooksPath .githooks
```

كل دفعة إلى `main` تشغّل التكامل المستمر في تبويب Actions.

## حدود معروفة

المشروع صفحات ثابتة بلا خادم، لذلك **كل التحقّق يجري داخل المتصفّح**. من يفتح
أدوات المطوّر يستطيع تجاوزه. الأمان الحقيقي يتطلّب خادماً يحفظ مفتاح TOTP سرّاً
ويتحقّق من توقيع WebAuthn ومن الواصف. ما هنا يوضّح التدفّق والتجربة بشكل صحيح
وكامل، لا أكثر.

بيانات كل حساب مرتبطة بمتصفّح الجهاز الذي سُجّلت منه، فالدخول من جهاز آخر يبدأ
تهيئة جديدة للعوامل.
